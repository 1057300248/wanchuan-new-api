## 后续复核发现与已直接写入的修正

此次提交把 15 个源文件/测试文件的修正直接写入代码，不能与尚未执行的补丁混淆。

### 1. 已输出失败流后的重试保护放错入口

原定制保护位于 controller.shouldRetry，但新的真实请求入口使用 service.DecideRelayRetry。只测试旧辅助函数会产生保护仍有效的错觉。

已在 service.DecideRelayRetry 的真实入口检查两类 handled-stream 标志，并让该检查优先于 channel-error 重试和剩余次数判断。Controller 回归已改为验证真实策略入口，service 层增加两个标志、两类错误、两个次数预算的组合测试。旧辅助函数的物理删除仍在 remaining.patch，不能宣称已从源码删掉。

### 2. 新图片协议绕过旧隐私边界

rc39 新增图片任务协议直接向调用者返回供应商错误码/原始消息，成功响应也可能暴露内部模型标识。

已把 controller/plugin_protocol_image.go 接入已有 SanitizeClientOpenAIError 与 SanitizeClientPayload。普通调用者即使登录身份是 admin/root，也不能自动得到渠道诊断；只有显式 ChannelTest 上下文保留诊断。新增专门隐私回归测试；内部稳定的图片失败/超时/取消错误码加入允许列表。原大文件中的旧图片错误断言适配尚在 remaining.patch，因此当前分支仍有已知测试调整待应用。

### 3. 新预扣测试与分账钱包不匹配

首轮官方新增数据库用例只设置 User.Quota，没有设置定制付费余额，也没有定制账本/请求幂等夹具。

已更新 controller/billing_option_test.go：注册 host 与定制钱包工厂，创建账本表，设置 QuotaPaid，提供唯一请求号，校验总余额与分账一致，并重复执行结算检验不重复扣款。没有放宽生产余额检查，也没有删掉失败用例。这些修正尚未获得第二轮测试通过证据。

### 4. 前端测试与定制契约不一致

已修正 StatusRecord 类型、CC Switch token-scoped 缓存夹具、注册/推广表单默认值、分组页面 section/baseline/onSave 契约、旧保存按钮选择器，以及管理员模型观察断言。另增普通用户看不到 legacy/admin_info 上游模型信息的测试。保留列定义 memo 优化及货币变更依赖，不删除依赖来压制告警。
